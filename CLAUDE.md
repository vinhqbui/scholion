# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Scholion: context-first version control for coding agents. Each task is an isolated jj workspace; decisions, attempts (dead ends) and notes are stored as records anchored to code; a deterministic, token-budgeted context pack hands any agent what it needs. The CLI is `scholion` with the alias `av` (same program); env vars keep the `AV_` prefix. Design: `docs/superpowers/specs/2026-10-18-agentvcs-design.md`. Implementation plans: `docs/superpowers/plans/` (Plans 1–5 are done; Plan 6, evaluation, is in progress; Plan 7, overlay index scopes, is merged; Plan 8, routing tasks to the agent that fits (backlog, agent profiles, `av next`), is merged; its evaluation is written but not run; Plan 9, closing the review loop (`next` offers reviews and merges first, rescues handoffs and abandoned tasks, waits; `av watch`), is merged. Release 0.0.2 (tag `release/0.0.2`, `CHANGELOG.md`) is the first to ship `scholion-daemon` with bundled Postgres). The spec and older plans use the earlier name `agentvcs` and crates `av-*`. The plan files' checkboxes and some signatures lag the code; when they disagree, the code wins.

## Commands

Rust is pinned to 1.97.1 (`rust-toolchain.toml`); do not change it in an unrelated change.

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace                       # all green is the bar before any commit
cargo test -p scholion-daemon --test api submit_  # one test file / name filter
cargo test -p scholion-semantic --test qdrant NAME -- --exact --nocapture
cargo build --release -p scholion-cli           # -> target/release/scholion and av
scripts/smoke.sh                             # end-to-end against the Docker stack; --down also deletes volumes
docker compose -f deploy/docker-compose.yml up -d --build   # needs `export UID GID=$(id -g)` first
```

Test environment:
- Postgres tests use `scholion_testutil::TestDb`: a fresh database on `AV_TEST_DATABASE_URL` if set, otherwise an embedded user-space Postgres (downloaded on first run). No Docker needed.
- Qdrant tests silently skip (pass in ~0s) unless `AV_TEST_QDRANT_URL` (gRPC, e.g. `http://127.0.0.1:6334`) is set. A green workspace run does not prove Qdrant works.
- `warm_build_under_300ms` is `#[ignore]`d (timing).
- Docker Desktop without WSL integration needs Windows-drive paths for bind mounts; see the README section of that name.

## Architecture

Cargo workspace, `crates/*`, edition 2024. A daemon (axum, `:7420`) owns all state; the `scholion` CLI (alias `av`) is a thin HTTP client.

- `scholion-core` — shared types, `AvError`, and the traits every unit talks through (`traits.rs`: `Vcs`, `IntentStore`, `Semantic`). `lifecycle.rs` is the pure task state machine (`next(status, Event)`); illegal transitions are `AvError::IllegalState` → HTTP 422 (`Invalid` stays 400 = malformed input).
- `scholion-vcs` — **the only crate that touches jj-lib** (pinned `=0.46.0`). Repos are git imports; one jj workspace per task. After any jj-lib rewrite call `rebase_descendants()`. `ChangeId` is the jj *commit id* hex, so any snapshot/squash/rebase produces a new id.
- `scholion-store` — Postgres `IntentStore` (sqlx, migrations in `crates/scholion-store/migrations/`, numbered `000N_*.sql`, embedded via `sqlx::migrate!`; two branches adding the same number break every DB test, so check `main`'s highest number before merging). A merged migration is never edited, not even a comment: databases store its checksum, and `tests/migrations_frozen.rs` pins each file's hash (add a line for a new migration). Postgres is the source of truth; the `repos` table (migration 0023) lists imported repos, written by the import and backfilled from the jj store at daemon start-up (`api::sync_repos`), and `GET /v1/repos` / `av repo list` read it. Writes that need embedding enqueue an `outbox` row in the same transaction (`outbox.rs`).
- `scholion-index` — tree-sitter (Rust, TS, Python) symbols, reference graph, skeletons and code chunks, stored in Postgres, incremental by content hash.
- `scholion-semantic` — `Embedder` (TEI, Ollama, `ScriptedEmbedder` fake) and `VectorIndex` (Qdrant, `MemoryIndex` fake). `Embedder::dimension` is `async` and fallible (the plan text says sync; the code is right). Qdrant is derived data, rebuildable with `av reindex`.
- `scholion-pack` — deterministic context packer, no LLM: seeds → candidates (structural, anchored records, semantic, live work) → scoring (lexical BM25 and semantic code hits count by rank, reciprocal rank fusion, `score::rrf_sim`) → budget split by section with spillover, and what the last section leaves upgrades earlier handles → progressive tiers (handle/summary/full) → session ledger so later packs reference instead of resend. Each pack stores a receipt (`rcp:<8 hex>`). Golden output in `tests/golden/`.
- `scholion-daemon` — `wiring.rs` builds `Config` from env and the `AppState`; `api.rs` routes (all under `/v1`); `worker.rs` drains the outbox into Qdrant every second; `embed_choice.rs` picks host Ollama `qwen3-embedding` first, else `AV_EMBED_URL`/`AV_EMBED_API_KEY`, else semantic off. If Qdrant/embedder fails, packs still return and are marked `degraded: semantic` (Postgres full-text instead). `ui.rs` + `ui.html`: the read-only dashboard at `/ui` (one static page, vanilla JS, embedded with `include_str!`; it only reads `/v1`; a Teams panel reads `/v1/agents`).
  - **`flow.rs` holds the Plan 3 lifecycle operations (submit, and next handoff/claim/review/merge/undo/backup).** The plan says a separate `av-flow` crate; that was overruled because each op needs `snapshot_and_index` from `api.rs`. Their tests go in `crates/scholion-daemon/tests/api.rs`; concurrency tests (many agents at once) in `tests/swarm.rs`. Both share `tests/common/mod.rs` (`env()`, `env_with()`, `env_with_vcs()`, `start_task`, `submit`, `edit_greeter`, `call`). Workspace operations on one task take `AppState::lock_task` first, then `flow::fence` (refuses writes under an older claim generation, header `X-Av-Generation`).
  - `ext.rs` — extension points for code built on the daemon (the commercial edition): `router_with` (extra routes behind the token), `AppState::with_extension`/`extension` (typed services), `subscribe_events` (lifecycle events in process), `MergeGuard` (asked before approve and merge; `AllowAll` here), `AppState::migrate_extension` (an extension's own migrations in its own Postgres schema with its own `_sqlx_migrations`, so its numbers never meet ours; tests in `scholion-store/tests/extension.rs`). Keep them stable: agentvcs builds on them.
  - `routing_api.rs` — Plan 8: `/v1/agents`, `/v1/backlog` and `POST /v1/backlog/next`. `next` (Plan 9, `choose` then `act`) offers, in order: reviews of others' in-review tasks (never the owner; only agents that fit the item's tags, unless only the owner fits; reserved 600 s per reviewer in `AppState.reviews`; approved ones say "merge it"), then handoffs (claimed; untagged ones keep their item's tags with the same exception), abandoned open tasks (lease ran out; the owner resumes via `flow::resume_as`) and queued items, ranked by the pure rules in `scholion-core/src/routing.rs` (`order_for_excluding`: the agent that handed a task off neither takes nor holds it). A profile's `max_open` (migration 0024; NULL = no limit) caps a team's open tasks: `within_limit` then keeps only reviews and the agent's own abandoned tasks, and the empty answer carries `at_capacity`. `wait_secs` loops `choose` (cap `MAX_WAIT_SECS` 50, `AppState::with_max_wait`); `dry_run` returns `{would}` and takes nothing (`av watch` polls it). MCP tools resolve `task_id` as id, slug or `repo/slug` (`mcp::task_ref`). Tests in `tests/routing.rs` and `tests/swarm.rs` (`swarm_loop_runs_backlog_to_merged`). An agent's MCP name is resolved through profile aliases at `initialize`. `start_task` with no `title`/`goal` is `next`; the tool list is size-guarded in `tests/mcp.rs`.
  - `mcp.rs` — the MCP server at `/mcp` (JSON-RPC over streamable HTTP, plain JSON responses; hand-rolled, no SDK). Each tool is an in-process request to `api::routes()`, so tools behave exactly like the HTTP API. A session remembers every task it started or claimed (Claude Code subagents share their parent's session, checked with a logging proxy); without `task_id` a call uses the only one, else the only open one, else refuses and names them (`target`). Tests in `tests/mcp.rs`.
- `scholion-bench` — the Plan 4 benchmark harness (`scholion-bench check|run|report|calibrate`). Pure analyzer (`events`, `metrics`, `report`, `stats`, `calibrate`); only `runner`/`orchestrate` start processes and only `run --confirm` spends money. Tests use a fake `claude` script and, for the av arms, a real daemon. Tasks and the run guide: `bench/` (`bench/README.md`). `bench/tasks-relay` is E4, the knowledge relay (arms `cold` (no lessons, the control), `baseline`, `notes`, `av`; `--jit-hooks`; `--price-per-mtok` for models Claude Code cannot price, e.g. DeepSeek). The av arms run on hooks + CLI unless `--av-mcp`; a spec's `path_prepend` puts dirs (the venv with pytest) first on the agent's PATH. Plan 6 adds `retrieval` (offline E1: scores first packs against three baselines, `--no-pack` needs no daemon, `--reuse-run ID` re-measures a new packer on repos an earlier run imported) and `mine` (builds retrieval tasks from a repo's history); task set and how to run it in `bench/retrieval/README.md`.
- `scholion-cli` — clap subcommands mirroring the API. `local.rs`: `av up`/`av down` (lite mode: the daemon runs its own Postgres when `AV_DATABASE_URL` is unset, `embedded_pg.rs`) and `av init`; `agents.rs`: `av init --for codex|grok|gemini|cursor` merges the MCP server into those CLIs' config files (Grok, Gemini and Cursor also get an `X-Av-Agent` header; Cursor's is `~/.cursor/mcp.json`). `av init --for mcp-json --path FILE` merges `{type: http, url, headers: {X-Av-Agent}}` into any `mcpServers` JSON file; `X-Av-Agent` is the global `--agent` name. Muse Code's own settings path is still unverified (`integrations/muse/README.md`); point `--path` at it once you know the file. Plan 8 adds `av agent set|list`, `av post`, `av backlog [drop]`, `av next` and `av handoff --needs`; Plan 9 `av next --wait` and `av watch` (`watch.rs`: polls a dry-run `next` and runs an agent command when work fits; the CLI may start processes, the daemon never does). Finds its task via the nearest `.av-task` file in the workspace; `AV_URL` / `AV_SESSION` override.
- `scholion-testutil` — `TestDb` only.

`integrations/` holds the agent glue: `claude-code/install.sh` installs `SessionStart` (prints a pack), `PreToolUse` on `Read|Edit|MultiEdit` (other tasks' records about that file, `GET /tasks/{id}/records/at`, each record once per session), `PostToolUse` (checkpoints) and `Stop` (asks once per session to record changes no record explains, `GET /tasks/{id}/unrecorded`) hooks that call `scholion hook session-start|pre-read|post-edit|stop`; `generic/av-wrap.sh` wraps any other agent. Pack code items carry path, lines and signature, not bodies, because Claude Code re-reads a file before editing it (see `bench/README.md`, "Haiku runs").

Invariants worth not breaking: record summaries ≤ 200 chars and records are append-only (newer ones *supersede*); `submit`/`handoff` are refused without an intent plus at least one decision/attempt/note/handoff record; `main` advances only via `merge` (or `revert`, which adds a commit); the daemon never runs repository commands (validations/checks are attestations reported by clients); workspace paths returned to clients are host paths (`ws_host_root`), not container paths; auth is the optional shared `AV_TOKEN` (every route but `/healthz` and `/ui`), so compose still binds everything to `127.0.0.1`.

## Working conventions

- `main` is the base. Start each change on a branch off `main` and land it through a pull request; prefer one PR per change over stacked PRs (a PR stacked on another merges into that branch, not `main`).
- Work is TDD: failing test first, then implementation, then fmt + clippy + tests. See `CONTRIBUTING.md`.
- Agent-facing text (pack output, MCP tool descriptions, hook messages) says `av`, not `scholion`: it is shorter for agents to type and both names are always installed.
